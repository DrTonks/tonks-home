## 头像与主题切换

调色盘增加「头像粒子」，默认关闭，桌面可主动开启并保存偏好。关闭时保留亮暗主题各自的静态头像，只执行原有整页圆形扩散，零 WebGL 初始化、无粒子缓冲和独立头像裁剪层。

移动端禁用粒子，范围包括窄屏和无 hover 的粗指针设备，因此横屏手机/宽屏纯触摸设备也不会因保存过开启偏好而初始化 GPU。系统要求减少动态效果时同样停用。跨设备边界、关闭选项或卸载组件会释放资源；返回允许条件后可以重新准备。

开启时整页与头像的两层裁剪使用一致的圆心、半径和时钟，防止边界不同步。同步不会消除额外截图、合成与内存成本，粒子绘制和更长的动画窗口也有开销。关闭时只用一个裁剪。

先前对远程原版与旧版的同机实验：常规桌面每次切换 P95 帧间隔的中位数都是 8.50ms；CPU 4 倍降速时旧版 16.70ms、新版 25.05ms。压力样本提示有退化风险，但 rAF 不是实际 GPU 呈现帧率，小样本不能代表固定的性能损失或所有低端设备。本轮的默认关闭与移动端禁用避免让所有访客承担粒子成本，未把功能 QA 冒充新的性能基准。

dist 包含全站页面、原图、优化图与脚本。浏览器只按页面引用请求资源，不会因为 dist 大而下载整个目录。保留未使用的原图主要增加服务器存储、部署传输/解压与备份占用；确实引用旧图的页面仍会下载旧图。某些页面的新脚本或多头像也有各自下载成本，不能由 dist 总量推出首屏快慢。

此前 Windows 生成的清单有反斜杠路径，页面没有实际命中优化图；本轮修复后，最终 HTML 中 163 个 src/srcset 属性引用 /_images/，项目、相册、首页和临时开启展示的文章封面均在实际浏览器中请求到 WebP。完整产物含 Astro 生成图片在内共 214 个 WebP，19,493,038 B。

WebP 的有损编码可能有细微像素差异，符合本轮接受范围；当前只选择比原件小的适用输出。原图继续保留，旧链接和手工管理不受破坏。现在不急于删除原图，后续依据真实引用、外链和预览需求优化部署副本即可。

## tonks-home WebP 评估

建议后续优先优化 CDN 桌面背景，不需要立即给所有图片统一换格式。本轮没有转换主页资源或改引用。

真实 GET 检查的 7 张背景均为 PNG，合计 8,908,219 B（8.50 MiB）；这不等于一次首屏都会下载它们。线上 l1.png 为 1,105,900 B，原尺寸 q85 WebP 内存样本为 69,666 B，潜在节省约 93.7%，需后续视觉验收。线上图与本地同名低分辨率回退不同，不能直接拿本地文件替换线上高清源。

其次考虑静态头像、移动背景和桌宠帧。Live2D 纹理需要单独核对模型路径/渲染；GIF 必须保留帧数、时序、循环与透明，不可转成单帧。小表情可能转后更大，不宜统一有损处理。

主页既有 dist 约 39.88 MiB，其中 WASM 和手部模型占 70.43%；WebP 无法减少这部分。CDN 图本身不在本地 dist，因此优化它们可以改善访客传输，却不会体现为本地 dist 明显缩小。主页项目卡片目前可收到博客图片 URL，但仍是原图路径，不会自动获得博客缩略图的节省；后续可以单独扩展缩略图契约。
