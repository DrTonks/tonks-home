# 桌宠表情池

## 当前行为

- 普瑞赛斯保留原 `pet-dialogue.json` 图片路径句库，由精选池映射到已有评论表情资源。旧条目被冷却拦截时使用自然短句兜底。
- U 酱使用独立的 2233 表情；两者共享咖啡、裹被与送花三张 Blobcat。图像不改变身体动作、情绪状态或 Live2D 参数。
- 本地问候、情绪、转身与普通闲聊沿用原触发时机。新增随机配图概率为老普 22%、U 酱 38%，选中已有图片句库条目时直接尝试该图。两者共享 45 秒发图冷却，最近三张不重复。原记忆句、天气播报、介绍、歌词及操作确认不自动配图。
- AI 必须回复文字，可选一张表情；前后端均校验角色允许列表。文字先完整显示并保留原阅读时间，随后同一气泡切换为约 112px 的独立表情，停留 3 秒；原有纯表情仍停留 4 秒。图片失败显示含义。AI 回复也遵守图片冷却，受限时只显示文字。
- 点击、拖动或打开右键菜单会取消尚未显示的表情，当前文字继续读完；新回复、歌词、提问或卸载会清除待发表情。45 秒冷却与去重在表情实际进入展示阶段时记录，取消的图片不占用冷却。
- 固定回答中的旧图片路径先解析，再添加“谢谢，已经收到推荐”等前缀，不会拼出坏图片地址。
- 切换角色卸载时取消请求；歌词、其它气泡或新请求替换后，旧请求结果和失败兜底都不再覆盖新内容。

## 配置与资源

唯一编辑源：`src/data/pet-reactions.json`。修改条目的 `token`、`description`、`pets`、`scenes` 即可调整表情池；旧句库的图片条目保留 `legacySrc` 和短句 `fallback`。

图片仍来自 `public/emojis/manifest.json` 及 `/emojis/v1/`；不新增图片存储、数据库、定时任务或环境变量。先看图确认含义，再写描述。

```sh
pnpm reactions:sync
pnpm reactions:check
```

同步脚本生成当前仓库的 `src/data/pet-reaction-assets.json` 和相邻 sleepy 仓库的 `pet_ai/reactions.json`。不要手工修改生成文件；两仓库配置要分别提交。脚本只写配置，不上传资源或部署。脚本要求本地存在相邻的 `../sleepy` 仓库。

## 接口兼容

`POST /pet/reply` 请求不变。SSE result 与普通 JSON 均保留 `reply`，新增可选 `emoji_id`，例如 `quiet_happy`。后端兼容模型旧纯文本；破损 JSON 进入既有错误/本地回复兜底。未知或越角色编号只丢弃配图。搜索仍使用既有工具流程，同一次最终回复选择表情，不增加模型调用轮次。

前端兼容未返回 emoji_id 的旧后端；旧前端仍可读取新后端 reply。发布可先后端再主页；图片新增时应先发布共享静态资源。本轮所选图片都已在已有清单中。

## 本地验收

`pnpm dev` 后访问 `/__design/pet-reactions/`，切换角色、选择图片、查看分段回复/纯图、测试取消后续表情、坏图及歌词替换。此页仅开发构建注册，不调用模型、不写入用户记忆。生产构建不包含该预览组件。

自动测试覆盖：角色池、共享冷却/去重、旧路径、气泡互斥与计时、SSE兼容和取消、迟到回复；sleepy 测试覆盖结构化解析、搜索与两种HTTP返回。真实模型的选图语气仍需部署前/后少量人工验收。
