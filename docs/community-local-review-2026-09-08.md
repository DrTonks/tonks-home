## 补充：线上博客置顶 HTTP 400（仅本地修复）

- 原因：博客 PATCH 置顶请求使用 JSON 字符串，却遗漏 `Content-Type: application/json`；浏览器默认为 `text/plain;charset=UTF-8`，Flask 无法解析 `is_pinned`，返回 `invalid_pin`。修复为 `adminHeaders(adminSecret, true)`，保留管理员鉴权。后端及主页 Axios 无需修改。
- 截图中的 Clarity 语法错误是另一问题：含 TypeScript 的脚本带 `type="text/javascript"`，绕过 Astro 转译。移除该属性，并保护整段初始化，避免脚本重跑时重复加载。
- 新增博客 `scripts/test-community-pin.mjs`：真实 Edge、真实评论 JS 与原生 fetch、本地模拟 API，复现旧请求 400，验证根留言和回复置顶/取消、置顶排序、无重复条目、刷新后的状态及请求头；验证 Clarity 经 Astro 提取和转译后执行，并检查重复执行不重复插入脚本。
- Harvey 使用隔离数据库和真实 Flask 路由验证缺失/文本类型请求返回 400，JSON 类型请求置顶及取消返回 200；缺失或错误管理员密钥返回 401，失败请求不改变状态。独立复审最终修复并重新运行浏览器测试，未发现阻塞问题。
- 覆盖限制：Clarity 测试模拟脚本重执行，未验证完整 Swup 导航和远程统计服务。此前审查未覆盖置顶请求的实际 HTTP 类型，本次补上该回归。
